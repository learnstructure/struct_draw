# struct_draw

**`struct_draw`** is a high-precision Python library for generating CAD structural engineering drawings (DXF format). It converts structural design parameters and detailing calculations into production-ready CAD drawings featuring plan views, sectional elevations, reinforcement detailing, dimension lines, grid axes, and native AutoCAD `MULTILEADER` annotations.

---

## Key Features & Capabilities

- **Production-Ready CAD Drawings**: Generates standard DXF files compatible with AutoCAD, BricsCAD, DraftSight, and LibreCAD.
- **Native AutoCAD `MULTILEADER` Entities**: Annotations for rebar, beams, and structural notes use CAD native `MULTILEADER` objects so text and leader arrows stay linked during manual CAD edits.
- **Dual Unit Support**: Full support for both **Imperial (US customary)** and **SI Metric** units, with explicit unit helper constructors (e.g., `IsolatedFootingData.from_metric(...)` / `FootingData.from_metric(...)`).
- **Comprehensive Structural Element Library**:
  - **General Arrangement (GA) Framing Plans & Elevations**: Complete building floor framing plans, frame elevations along grid lines, and roof trusses directly from a `StructuralModel` or `Project`, showing columns, beams, braces, grid bubbles, story levels, bay dimensions, and member marks without requiring prior rebar design.
  - **Spread / Isolated Footings**: Plan and section views, sloped/stepped footing geometry, column dowels, hook bends, distribution mats, GL (Ground Level) / PL (Plinth Level) markers, and grid axes.
  - **Combined Footings**: Multi-column support, top & bottom longitudinal/transverse rebar mats, column starter dowels, dimensioning with clear vertical hierarchy (span dimensions, overall length, and section title neatly placed below all dimensions), and schedule tables.
  - **Staircases**: Waist-slab staircases featuring flight elevations, treads & risers, support beams, scissor/crank rebar at landing junctions, top & bottom extra support bars, distribution rebar, step nosing bars, binders, and plan view UP walklines.
  - **Beams & Columns**: Elevation and section reinforcement views, double-line closed stirrups with professional 135° seismic hooks tangent to corner longitudinal bars (with perpendicular end-caps and continuous inner contour), development length $L_d$, and schedule tables.
  - **Slabs**: One-way and two-way slab sectional reinforcement details.
- **Design Framework Adapters**: Seamlessly translates design results from structural design tools (e.g., `aci318`) into drawing data models.

## Unit Systems, Drawing Scales & Plotted Drafting Standards

`struct_draw` features full unit-system awareness and drawing scale factor integration linked directly with `struct_core.units.Units` (`Project.metadata.units`).

### Universal Plotted Drafting Standard

Every drawing generated by `struct_draw` complies with the universal architectural/structural drafting standards for paper prints:

| Element | Target Plotted Paper Size | Standard Metric Scale ($1:100$) | Standard Metric Detail ($1:20$) | Standard Imperial Scale ($1/4"=1'-0"$) |
| :--- | :---: | :---: | :---: | :---: |
| **Dimension Text** | **$2.0\text{ mm}$** | $200\text{ mm}$ | $40\text{ mm}$ | $3.78"$ |
| **Dimension Arrowheads / Ticks** | **$2.0\text{ mm}$** | $200\text{ mm}$ | $40\text{ mm}$ | $3.78"$ |
| **General Text / Member Notes** | **$3.0\text{ mm}$** | $300\text{ mm}$ | $60\text{ mm}$ | $5.67"$ |
| **View Titles** | **$5.0\text{ mm}$** | $500\text{ mm}$ | $100\text{ mm}$ | $9.45"$ |
| **View Subtitles / Scale Labels** | **$3.5\text{ mm}$** | $350\text{ mm}$ | $70\text{ mm}$ | $6.61"$ |
| **Grid Bubble Radius** | **$4.0\text{ mm}$** | $400\text{ mm}$ | $80\text{ mm}$ | $7.56"$ |
| **Dimension Offset Clearance** | **$6.0\text{ mm}$** | $600\text{ mm}$ | $120\text{ mm}$ | $11.34"$ |
| **Extension Line Overhang** | **$2.0\text{ mm}$** | $200\text{ mm}$ | $40\text{ mm}$ | $3.78"$ |

The modelspace size $H_{\text{model}}$ is computed using the exact scaling formula:
$$H_{\text{model}} = H_{\text{print}} \times \left(\frac{1}{\text{Unit to mm}}\right) \times S$$
where $S$ is the scale denominator (e.g., $100$ for $1:100$, $50$ for $1:50$, $48$ for $1/4"=1'-0"$).

### Scale Presets & Custom Scales

```python
from struct_draw.core.units import (
    DrawingScale,
    DrawingUnit,
    SCALE_1_100,  # 1:100 (Framing Plans)
    SCALE_1_50,   # 1:50 (Elevations, sections)
    SCALE_1_30,   # 1:30 (Beam cross-sections)
    SCALE_1_25,   # 1:25 (Reinforcement detailing)
    SCALE_1_20,   # 1:20 (Member cross-sections)
    SCALE_1_10,   # 1:10 (Connection details)
    SCALE_1_8_IN, # 1/8" = 1'-0" (Imperial plans)
    SCALE_1_4_IN, # 1/4" = 1'-0" (Imperial elevations)
    SCALE_1_2_IN, # 1/2" = 1'-0" (Imperial details / footings / cross-sections)
    SCALE_1_IN,   # 1" = 1'-0" (Imperial details)
)

# Parse from text or custom ratio:
scale_metric = DrawingScale.from_str("1:50")
scale_imperial = DrawingScale.from_str('1/4"=1\'-0"')
```

### Automatic View Defaults

When `scale` is not explicitly specified, `struct_draw` automatically applies the industry standard drafting scale for each specific view type based on whether the unit system is SI Metric ($mm$) or US Customary ($in$):

| View Type | Metric Default ($mm$) | Imperial Default ($in$) | Description |
| :--- | :---: | :---: | :--- |
| **Floor Framing Plan** | `SCALE_1_100` ($1:100$) | `SCALE_1_8_IN` ($1/8"=1'-0"$) | General arrangement building floor layouts |
| **Frame Elevation** | `SCALE_1_50` ($1:50$) | `SCALE_1_4_IN` ($1/4"=1'-0"$) | Column grid elevations, trusses, story levels |
| **Beam Profile / Elevation** | `SCALE_1_25` ($1:25$) | `SCALE_1_2_IN` ($1/2"=1'-0"$) | Continuous beam longitudinal profiles |
| **Footings (Spread / Combined)**| `SCALE_1_25` ($1:25$) | `SCALE_1_2_IN` ($1/2"=1'-0"$) | Footing plan and section views |
| **Staircases** | `SCALE_1_25` ($1:25$) | `SCALE_1_IN` ($1"=1'-0"$) | Flight elevation, landing joints, steps |
| **Slab Plan** | `SCALE_1_50` ($1:50$) | `SCALE_1_4_IN` ($1/4"=1'-0"$) | Slab panel layouts |
| **Beam Cross-Sections** | `SCALE_1_30` ($1:30$) | `SCALE_1_2_IN` ($1/2"=1'-0"$) | Beam cross-sections with rebar callouts |
| **Member Cross-Sections** | `SCALE_1_20` ($1:20$) | `SCALE_1_IN` ($1"=1'-0"$) | Column, wall, and detail cross-sections |

You can query or inspect defaults programmatically using:
```python
from struct_draw import default_scale_for_view

plan_scale = default_scale_for_view("plan", is_metric=True)       # DrawingScale(1:100)
elev_scale = default_scale_for_view("elevation", is_metric=True)  # DrawingScale(1:50)
beam_scale = default_scale_for_view("beam", is_metric=True)       # DrawingScale(1:30)
detail_scale = default_scale_for_view("detail", is_metric=True)   # DrawingScale(1:20)
```

### Auto-Detection from `struct_core.Project`

When rendering from a `Project`, `struct_draw` automatically inspects `Project.metadata.units`:
- **SI Metric** models ($m$ coords, $m$ or $mm$ sections) are scaled automatically by $1000\times$ into millimeters. Plans use $1:100$, elevations use $1:50$, and rebar sections use $1:20$.
- **US Customary** models ($ft$ coords, $in$ sections) are scaled automatically by $12\times$ into inches. Plans use $1/8"=1'-0"$, elevations use $1/4"=1'-0"$, and rebar sections use $1"=1'-0"$.
- Custom scales and target units can always be overridden directly in `draw_from_core(...)` and `draw_general_frame_from_core(...)`.

## General Arrangement (GA) Framing Drawings from StructuralModel

Generate architectural/structural general arrangement drawings directly from any `struct_core.StructuralModel` or `Project`:

```python
from struct_draw import (
    draw_framing_plan_from_core,
    draw_frame_elevation_from_core,
    draw_general_frame_from_core,
)

# 1. Floor framing plan at specific story level (e.g. FL1 or ROOF)
draw_framing_plan_from_core(
    project,
    story_level="FL1",
    output_path="framing_plan_fl1.dxf",
)

# 2. Frame elevation along a grid line (e.g. Grid 1 or Grid A)
draw_frame_elevation_from_core(
    project,
    grid_line="1",
    output_path="frame_elevation_grid1.dxf",
)

# 3. Combined plan & elevation drawing sheet
draw_general_frame_from_core(
    project,
    view_mode="both",
    story_level="ROOF",
    grid_line="1",
    output_path="framing_combined_sheet.dxf",
)
```

- **Synchronized Member Mark Hierarchy**: Member marks (`B2`, `C1`, `C3`) are systematically synchronized across framing plans, frame elevations, and detailing section cuts based on element attributes or element IDs to ensure 100% drawing consistency.

## Quick Start Example: Spread Footing

Here is a complete example of generating a spread footing drawing (Plan + Section) in **SI Metric units**:

```python
from pathlib import Path
import struct_draw as sd
from struct_draw.core.data import IsolatedFootingData, FootingData, Rebar, Stirrup

# 1. Define Footing Parameters in SI Metric Units (mm)
footing_si = IsolatedFootingData.from_metric(
    name="F2",
    length=1600.0,              # Footing length (1600 mm)
    width=1600.0,               # Footing width (1600 mm)
    mid_thick=400.0,            # Central footing thickness (400 mm)
    edge_thick=200.0,           # Edge footing thickness (200 mm)
    col_width=350.0,            # Column width (350 mm)
    col_depth=350.0,            # Column depth (350 mm)
    col_height=2100.0,          # Column height above footing (2100 mm)
    fd_depth=1500.0,            # Foundation depth below Ground Level (1500 mm)
    pl_height=600.0,            # Plinth Level height above Ground Level (600 mm)
    cover=75.0,                 # Concrete clear cover (75 mm)
    bar_dia=12.0,               # Footing mat rebar diameter (12 mm)
    bar_spacing=150.0,          # Rebar spacing center-to-center (150 mm c/c)
    ld=600.0,                   # Development length Ld (600 mm)
    column_bars=(
        Rebar(mark="C1", size="16mm dia", quantity=4, length_in=3000.0),
    ),
    column_stirrups=Stirrup(size="8mm dia", spacing_in=100.0, legs=2),
)

# 2. Render and save to DXF
output_path = Path("footing_drawing_si.dxf")
sd.save_dxf(footing_si, output_path)

print(f"Footing DXF successfully created at: {output_path.resolve()}")
```

### Imperial Units Example

`struct_draw` also accepts Imperial parameters directly:

```python
import struct_draw as sd
from struct_draw.core.data import IsolatedFootingData, FootingData, Rebar, Stirrup

footing_us = IsolatedFootingData(
    name="F1",
    length_in=72.0,             # 6 ft length
    width_in=72.0,              # 6 ft width
    mid_thickness_in=18.0,      # 1.5 ft thickness
    edge_thickness_in=10.0,
    column_width_in=16.0,       # Column width
    column_depth_in=16.0,       # Column depth
    cover_in=3.0,               # Clear cover
    bar_dia_in=0.625,           # #5 rebar
    bar_spacing_in=6.0,         # 6" c/c
    column_bars=(Rebar(mark="C1", size="#6", quantity=4),),
    column_stirrups=Stirrup(size="#3", spacing_in=4.0, legs=2),
)

sd.save_dxf(footing_us, "footing_drawing_us.dxf")
```

## Bar Bending Schedule (BBS) Tables

`struct_draw` includes built-in support for generating production-grade **Bar Bending Schedules (BBS)** complying with ACI and international detailing conventions:

- **Multi-Tier Header Layout**: Standard columns `MARK | BAR SIZE | QTY (NO.) | LENGTH (ft-in or mm) | SHAPE (TYPE) | UNIT WT | TOTAL WT | REMARKS`.
- **Automatic Unit Weight Calculations**: Built-in weight tables for standard ASTM A615 imperial sizes (`#3` to `#18` in $lbs/ft$) and metric bar diameters per IS 1786 / EN 10080 ($kg/m$ via $d^2 / 162.2$).
- **Grand Total Weight Summary**: Computes total estimated reinforcement tonnage/weight and adds a summary row.
- **Dynamic Formatting & Clean Centering**: Dynamic column width calculation prevents text overlap; supports `align="center"`, `align="left"`, and `align="right"` for seamless alignment under foundation pads and column views.
- **Direct Element Integration**: Simply attach a `schedule` tuple of `ScheduleRow` objects to `IsolatedFootingData` (or `FootingData`), `CombinedFootingData`, or `ColumnData`:

```python
from struct_draw.core.data import IsolatedFootingData, ScheduleRow, Rebar, Stirrup
import struct_draw as sd

footing = IsolatedFootingData.from_metric(
    name="F1",
    length=1800.0,
    width=1800.0,
    schedule=(
        ScheduleRow(mark="F1-B1", size="12φ", quantity=12, length_in=1850.0, remarks="Bottom X-Dir Mat"),
        ScheduleRow(mark="F1-B2", size="12φ", quantity=12, length_in=1850.0, remarks="Bottom Y-Dir Mat"),
        ScheduleRow(mark="F1-D1", size="16φ", quantity=4, length_in=3000.0, remarks="Column Starter Dowels"),
        ScheduleRow(mark="F1-T1", size="8φ", quantity=20, length_in=1280.0, remarks="Column Ties @ 100mm c/c"),
    ),
)

# Renders Plan, Section, and centered Bar Bending Schedule table
sd.save_dxf(footing, "footing_with_schedule.dxf")
```

Or render a standalone schedule table sheet using `ScheduleTableData`:

```python
from struct_draw.core.data import ScheduleTableData, ScheduleRow

schedule_sheet = ScheduleTableData(
    title="PROJECT FOUNDATION REBAR SCHEDULE",
    rows=[
        ScheduleRow(mark="F1-1", size="#6", quantity=24, length_in=90.0, remarks="Footing F1 Bottom Mat"),
        ScheduleRow(mark="CF1-1", size="#7", quantity=16, length_in=180.0, remarks="Combined CF1 Longitudinal"),
    ],
    unit="in",
)
sd.save_dxf(schedule_sheet, "schedule_table_sheet.dxf")
```

## Project Structure & Architecture

`struct_draw` follows a clean modular design that separates data models, CAD rendering primitives, structural element generators, CAD styling, and export backends:

```text
struct_draw/
├── __init__.py                # Top-level exports and high-level drawing/saving API functions
├── version.py                 # Package version definition
├── adapters/                  # Producer-result -> struct_draw dataclass adapters
│   ├── __init__.py
│   ├── aci318.py              # Reads aci318 result objects by attribute name only
│   └── struct_core_adapter.py # Translates struct_core DesignResult/DetailingResult -> struct_draw Data models (ecosystem entry point)
├── backends/                  # Drawing-format backends (DXF today; PDF / IFC / SVG planned)
│   └── __init__.py            # ezdxf document creation, layer setup, DXF dispatch + save_dxf()
├── core/                      # Drawing-side data classes, primitives, and helpers
│   ├── __init__.py
│   ├── data.py                # Strongly-typed dataclasses for structural parameters & rebar specs
│   ├── primitives.py          # Basic CAD entities (lines, polylines, circles, rectangles, text, leaders)
│   ├── composite.py           # High-level CAD details (rebar hooks, dimensions, grid bubbles, section callouts)
│   ├── document.py            # Document wrapper for layer, block, and viewport management
│   ├── geometry.py            # Geometric transforms, vectors, and bounding box calculations
│   ├── sheet.py               # Sheet border layouts, title blocks, and drawing scale handling
│   └── viewport.py            # CAD viewport configuration and layout scaling
├── elements/                  # Structural member drawing engines (Generates complete detailing drawings)
│   ├── __init__.py
│   ├── beam.py                # Reinforced concrete beam elevation, section cuts, & stirrup zones
│   ├── beam_profile.py        # Beam profile / span elevation drawings
│   ├── column.py              # Column elevation, cross-sections, & tie arrangements
│   ├── combined_footing.py    # Combined multi-column footing detailing & schedule tables
│   ├── footing.py             # Spread / isolated footing detailing (Plan & Section views)
│   ├── slab.py                # One-way and two-way slab sectional reinforcement details
│   └── staircase.py           # Waist-slab staircase elevation, flight details, treads & risers
├── style/                     # Drawing-side style registries (layers, linetypes, text, dimensions, blocks)
│   ├── __init__.py
│   ├── blocks.py              # Standard CAD blocks (north arrow, section arrows, level symbols)
│   ├── dimension_styles.py    # Dimension line arrowheads, tick marks, and formatting
│   ├── layers.py              # Standardized CAD layer definitions and color mappings (ACI/AIA standards)
│   ├── linetypes.py           # Custom CAD linetype definitions (hidden, centerline, phantom)
│   └── text_styles.py         # Text font styles and character heights
└── utils/                     # Helper utilities and error handling
    ├── __init__.py
    ├── constants.py           # Physical constants, conversion factors (mm to inches), and defaults
    ├── exceptions.py          # Custom exception hierarchy (DrawError, ValidationError, BackendError)
    └── geometry.py            # 2D vector mathematics and intersection helpers
```

### Ecosystem integration

`struct_draw` is the dedicated drawing-generation layer of the [Structural Engineering Ecosystem](https://github.com/...). It consumes `DesignResult` and `DetailingResult` objects from [`struct_core`](https://github.com/...) (produced by [`aci318`](https://github.com/...)) and never re-implements engineering logic. The recommended end-to-end usage is:

```python
from struct_core import Project
from fem2d.adapters import model_from_core, result_to_core
from aci318.adapters import design_from_core
from struct_draw.adapters import draw_from_core

structure = model_from_core(project, load_case_id="Gravity")
structure.solve()
project.analysis_results["Static_1"] = result_to_core(structure, analysis_case_id="Static_1")

design_res, detail_res = design_from_core(project)
project.design_results["ACI318_19"] = design_res
project.detailing_results["ACI318_19"] = detail_res

output = draw_from_core(project)
output["drawing"].saveas("portal_frame_detailing.dxf")
```

A runnable example lives at `struct_agent/examples/end_to_end_ecosystem_pipeline.py` and `struct_agent/examples/demo_pipeline.py`.

### Automated Layout & Framing Integration
When generating full-sheet drawings containing both structural framing (plans and elevations) and member detailing cuts:
- **Unified Detailing Datum**: Computes a synchronized `detailing_baseline_y` below framing views with proper vertical headroom so tall elements (such as full-story columns with seismic confinement zones, lap splices, and upper/lower joint stubs) align cleanly with beam sections without vertical overlap or collision with framing views.
- **Dynamic Geometric Inference**: Automatically derives member clear lengths and section heights across `StructuralModel.nodes` (supporting both dict and list node collections), element definitions, and analysis/design cases in both SI Metric and Imperial US Customary units.

Generated DXF drawings organize entities onto standard CAD layers:

| Layer Name | Description |
| :--- | :--- |
| `CONC_OUTLINE` / `Slab` / `Beam` | Concrete outlines and member boundaries |
| `Rebar` / `REBAR` | Main longitudinal and flexural reinforcement |
| `Rebar_hatch` | Transverse / distribution rebar dots |
| `Stirrup` | Column ties, beam stirrups, and nosing binders |
| `Dimension` | Linear and aligned dimension lines |
| `CENTERLINE` | Column and grid centerline axes |
| `SECTION` | Section cut lines and callout symbols |
| `Text` | Annotations, titles, and multileader text |

## Ecosystem Position

`struct_draw` is the dedicated drawing-generation layer of the Structural Engineering Ecosystem. It **only renders** — it never performs FEM analysis, dynamics, RC design, or detailing decisions. All reinforcement information comes from `aci318.DetailingResult`. For the full architecture see the [root `agent.md`](https://github.com/...) and [aci318's `agent.md`](https://github.com/...).
